Verified fictional case detail uses its S-prefixed reference as the ONLY synthetic marker. No synthetic, fictional, illustrative or offline qualifiers elsewhere in that case presentation. Keep actual prerequisites at the relevant controls and retain historical real-person warnings.

**Why:** The product owner repeatedly required normal case/action presentation and explicitly rejected journey-level qualifiers and repeated banners; the S-number alone provides the context.

**How to apply:** Project only fixed catalogue/schema descriptions under live field permissions. Fictional origin is not permission to disclose mutable notes, documents, findings or history. Current prepared/activated operational facts must never be replaced by fictional source descriptions.

actions, not older specialist/agent aliases. Present authored case actions
normally while retaining read-only provenance separately from genuine history.

**Why:** The product owner explicitly requires the current catalogue agents to
be visible performing the requested case work, rather than generic review
placeholders or repeated explanations about illustrations.

**How to apply:** Include relevant Document Verification, Assets & Workplace
and Systems Watcher responsibilities without inventing actual provider receipts,
principal invocation, permissions or professional decisions.

The coordinating agent is the default current owner. Only an actual unresolved Action Center assignment establishes a human/team handoff; blocked/offline status does not.

**Why:** The product owner wants the responsible actor visible without fabricated assignees or an implication that inactive examples are executing.

**How to apply:** Keep the coordinating agent separately visible during human handoffs and return current ownership to it after resolution. Respect the append-only ledger's reassignment and resolution semantics.

verified fictional inventory, superseding the prior pending-only illustration

authorize operational completion or re-enable retired simulation.

**Why:** Request handling needs to be understandable end to end, including
unsuccessful outcomes, without changing genuine history or measured results.

**How to apply:** Keep story dates, roles, evidence, decisions and messages
