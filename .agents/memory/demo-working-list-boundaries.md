---
name: Demo working-list boundaries
description: The product scope for reversible per-case curation in Demo Organization.
---

Demo Organization's normal curation controls are tenant-shared, reversible Cases-list visibility for explicitly selected individual Onboarding and Offboarding cases only. Do not infer a selection or fabricate genuine requests.

**Why:** The user chose hiding instead of deletion to retain selected old cases beside future genuine requests. Existing history filtering is not selective hiding.

**How to apply:** Keep this preference independent of status, provenance, history filters, operational work, alerts, Action Center eligibility and Dashboard/Analytics totals. Other tenants, families and workforce-transfer programs are outside this curation scope. New records stay visible unless explicitly selected later.

The user later chose simple per-row check/uncheck over multi-selection and a review dialog. Keep a clear on-page explanation of what changes, and preserve live authorization and stale-write fencing for each toggle.

Separately, the user authorized one-time permanent cleanup and agent-chosen retention in the **current task Preview** only, not the main or published app. This is not permission to restore a general deletion/reset product feature or repeat cleanup after merge.

**Why:** On 2026-10-15 the user explicitly changed their one-time data instruction from hiding to deletion, then identified the current task's Demo Organization as the target. Task and main Preview data can differ.

**How to apply:** Do not replay that maintenance against another environment. Keep ordinary visibility behavior non-destructive, preserve existing dispatch/hold/file safeguards and external-effect audit evidence, and never label historical or blocked cases as newly created live requests.
