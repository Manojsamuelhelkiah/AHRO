Update **ONLY the existing Case Details page** that opens when a user clicks **View Details** from the Cases page.

The goal is to transform the current long, scroll-heavy Case Details screen into a **premium enterprise HRO case workspace** with strong information hierarchy, minimal scrolling, clear human-in-the-loop actions, and a professional SaaS experience.

Do NOT modify the Cases list page, Control Tower, Analytics, login page, authentication, database schema, or unrelated pages.

Do NOT break existing case functionality.

---

# 1. CORE DESIGN PRINCIPLE

The current Case Details page combines too much information at the same time:

* readiness
* documents
* agent activity
* communications
* AI plan
* technical rules
* approvals

This creates excessive scrolling and makes it difficult to understand what requires attention.

Redesign the page around:

**Who / What → Current State → Health → Human Attention → Next Actions → Recent Activity → Deep Detail**

The Case Overview should be a **decision workspace**, not an audit log.

---

# 2. PAGE STRUCTURE

The new Case Details page should follow this structure:

### Sticky Case Header

↓

### Case Health Summary

↓

### Tabs

`Overview | Tasks | Documents | Activity | Communications | Audit`

↓

### Overview

Main workspace:

**Left ~70%**

* Case Readiness
* Next Actions
* Recent Activity

**Right ~30%**

* Attention Required
* Case Owner
* Latest Communication
* Documents summary

The right rail should remain sticky on desktop.

This structure is the primary redesign requirement.

# 35. ACCEPTANCE CRITERIA

The Case Details redesign is complete only when:

* The page uses the approved case-details HTML concept as the visual reference.
* Case header is compact and sticky.
* Worker/contact information is no longer overloaded into the header.
* Case health is summarized immediately below the header.
* Tabs exist:

  * Overview
  * Tasks
  * Documents
  * Activity
  * Communications
  * Audit
* Overview is the default tab.
* Overview prioritizes decisions and current state.
* Readiness is condensed.
* Next Actions replaces the long AI Plan Summary on Overview.
* Attention Required is prominent when human action is required.
* Recent Activity is concise.
* Full activity exists in Activity.
* Technical trace exists in Audit.
* Full communications exist in Communications.
* Full document checklist exists in Documents.
* Full workflow exists in Tasks.
* Simulation controls are removed from the normal production case workspace.
* Long raw AI reasoning is not shown on Overview.
* Human-in-the-loop is represented as governance, not failure.
* Right rail is sticky on desktop.
* Primary Overview requires substantially less scrolling.
* Desktop layout is approximately 70/30.
* Mobile/tablet layout is responsive.
* The page works for HRO case types beyond onboarding.
* Existing functionality remains intact.
* No fake operational data is introduced.
* The page visually matches the Agentic HRO Design System V2.

The final result should feel like a **real enterprise case-management workspace for autonomous HR operations**, not a developer console, simulation screen, or collection of stacked dashboards.

The user should be able to open a case and understand within seconds:

**Who is this case about?**

**What is its current state?**

**Is anything at risk?**

**Does a human need to act?**

**What should happen next?**

**Where can I inspect the detailed evidence?**
