Evidence boundary: This guide describes product operation and test evidence. Reference coverage is a catalog mapping, not an executed assertion or proof that a test passed. Product-operation and UAT boundary

Product-guide instructions describe authorized real operation; they do not make generic Case, Batch, Transfer, configuration, or provider actions isolated UAT flows. For a simulated scenario, start in Test Center and use only its run-owned linked case, candidate portal, or evaluator. The evaluator may use actual production pure predicates only on run-owned fixture/snapshot state. It must not mutate real-case readiness, dispatch providers, or change global time, credentials, leases, or real deadlines. If a real workflow, specialist role, approval, or provider is required, record Manual or Blocked.

Standard and lateral lifecycle: Gateway A/B/C

Roles: HR coordinator · candidate · HR reviewer · Entry: /cases · /cases/:id · /candidate

This is an authorized product-operation guide: create a case only under normal business authority. It does not make generic Cases creation an isolated UAT flow. For UAT, start Test Center and use only the run-owned linked case, portal or evaluator. Gateway A checks complete intake, Gateway B routes BGV exceptions, and Gateway C is the final readiness boundary.

How to use this area

  • In authorized product operation, confirm legal name, role, business unit, joining date, manager and location through the visible workflow. For UAT, do not use this create flow; use the Test Center run link.
  • At Gateway A, send a deficiency only for listed missing items; return to intake after correction and escalate no-response through the visible SLA path.
  • At Gateway B, an adverse/disputed result goes to HR/Compliance; analysts do not self-disposition.
  • At Gateway C, inspect each mandatory workstream plus fresh approval. Do not release access/assets based on score alone.

Evidence to retain

  • Case header, checklist states, workstream owner/status, redacted communication record, audit timestamps.

Exceptions and boundaries

  • Start-date, manager or role changes require the current workflow/review; do not overwrite a stale view.
  • Conditional join is disabled unless approved tenant policy explicitly enables it.

UAT Test Center: run, evidence and safe cleanup

Roles: Organization member · test coordinator · Entry: /uat/

Select a role-appropriate scenario, create a tenant-scoped synthetic run, then use only its linked synthetic case, candidate portal or run-owned evaluator. Record observed evidence, pause/resume, export and clean only run-owned state. Reference coverage is a catalog mapping; only a recorded run can make an execution assertion.

How to use this area

  • Read scenario prerequisites, actor assignment, test mode and blocker before creating the run. If a role, provider or real workflow is required, record Manual or Blocked rather than using a generic product create action.
  • Use the fixture manifest and harmless files as inputs, not pre-verified outcomes; capture displayed local parse/content-rule state separately from scanner, authenticity and provider observations.
  • Record Passed, Failed, Blocked or Not applicable with a redacted reason. A safely blocked negative action can pass its test, while the unavailable capability remains blocked.
  • Use the run-scoped clock/exchanges and evaluator only for run-owned simulation. It can apply production pure predicates to run state but must never change real-case readiness; export before scoped cleanup.

Evidence to retain

  • Run/catalog/baseline version, linked-subject/evaluator reference, fixture seed, step history, provenance, report export and cleanup receipt.

Exceptions and boundaries

  • Test Center does not impersonate/promote users, authorize real recipients, dispatch providers or make generic Case/Batch/Transfer creation isolated.
  • Simulation evidence cannot clear real quarantine, certify vendors, assert scanner/authenticity outcomes, or establish live readiness.

Scenario instructions

UAT-STD-01 — Standard hire: guided intake to Day-1 review

Family: standard/lateral · Mode: simulated · Availability: available

Exercises a fictional standard case through intake, portal, checklist gates, work items and readiness review.

Execution boundary: Start in Test Center. Use only this run's linked synthetic case, candidate portal or run-owned evaluator; never create or mutate an ordinary Cases, Batch, or Transfer record to execute a simulated test.

Roles: HR coordinator · candidate · HR reviewer

  1. HR coordinator: From the Test Center run, open only its run-owned linked standard-hire case/evaluator and record the displayed case link or fixture ID; do not use generic Cases > Create.
    Expected: The run-owned subject has its own scope, current owner, joining date and pending workstreams without mutating a real case or readiness.
    Evidence: Redacted run header, linked-subject reference and evaluator result.
    Wait: Wait for run/link creation once; do not submit twice.
    Negative path: Use the run evaluator's incomplete-intake fixture and confirm its visible validation result.
  2. candidate: Open only the Test Center run's linked candidate portal and submit one harmless labeled fixture.
    Expected: The fixture is associated with the run-owned subject and may show a local validation result; source authenticity remains unverified.
    Evidence: Run-linked portal confirmation and redacted local status.
    Wait: Refresh the run-linked Documents view once after upload.
    Negative path: Use the supplied harmless unsupported-name/type fixture; do not upload executable or malware content.
  3. HR reviewer: Use the run-owned evaluator to inspect Gateway A, B and C and evaluate reopening a completed mandatory item with a QA reason.
    Expected: The production gate predicates are evaluated against run-owned fixture state only; an unmet item prevents simulated progression without changing any real case readiness.
    Evidence: Evaluator before/after result, reason and run evidence.
    Wait: Use displayed evaluator state; no provider wait is implied.
    Negative path: Evaluate unresolved BGV or mandatory readiness fixture state and confirm the simulated block.

UAT-FLT-01 — Frontline / bulk readiness and SLA

Family: frontline/campus bulk · Mode: simulated · Availability: available

Exercises capacity-aware frontline batch intake, independent medical/safety gates, and a run-scoped calendar boundary.

Execution boundary: Start in Test Center. Use only this run's linked synthetic case, candidate portal or run-owned evaluator; never create or mutate an ordinary Cases, Batch, or Transfer record to execute a simulated test.

Roles: TA intake · site coordinator · EHS reviewer

  1. TA intake: From Test Center, open the run-owned batch evaluator/linked fixture with role, site, shift and skill category; do not use Batch intake to create a cohort.
    Expected: Valid fixture rows continue as a cohort while the invalid row is separately reported; no ordinary batch is committed.
    Evidence: Run fixture reference and evaluator row-level result.
    Wait: Wait for the run-owned preview/evaluation.
    Negative path: Evaluate the supplied regulated-role fixture with missing age proof or skill evidence.
  2. site coordinator: Use the run-owned evaluator to set simulated medical-fit, BGV and PPE fixture states, leaving safety competency unsigned.
    Expected: Production pure gate predicates show that score cannot make the fixture floor-ready while safety or medical hard gates are open; no real readiness is mutated.
    Evidence: Run evaluator gate result and simulated-evidence note.
    Wait: Do not interpret a simulated result as occupational-health evidence.
    Negative path: Evaluate floor release before the safety sign-off.
  3. EHS reviewer: Advance only the run clock across a shift/timezone boundary and inspect SLA escalation.
    Expected: Only run-owned watches react; production time, leases and real deadlines are unchanged.
    Evidence: Clock history and simulated escalation.
    Wait: Advance 24 hours, then refresh the run.
    Negative path: Record a PPE stock-out or failed competency and confirm retraining/hold rather than release.

UAT-XFR-01 — Workforce transfer continuity and cutover
